# Ecological dynamics laboratory implementation plan

The [submitted paper](../paper/2521959.pdf) and [audit](MODEL_TRACEABILITY.md) establish the mathematical definitions. The [figure atlas](FIGURE_ATLAS.md) preserves historical results separately. The [storyboard](RESEARCH_STORYBOARD.md) carries the research narrative.

| Original 2025 mathematical definition, [Eq. 7, p. 11](../paper/2521959.pdf#page=11) | Two age-dependent densities. ## Numerical and product plan

1. Capture the legacy default trajectory as a regression reference. Put scenario metadata and numeric settings in a shared machine-readable manifest. Implement strict input validation, integer step counts, explicitly aligned grids and finite checks.
2. Use Euler–Maruyama with standard normal increments scaled by the square root of the step. For the independent model, the prior projection to [0, 80] prevents negative or runaway values. Count boundary interventions. Projection can bias the process, and a zero state is absorbing in this model. For the Eq. 10 example, surface an invalid numerical state as a solver error. Use analytical reference tests and timestep refinement to assess accuracy within tested conditions.
3. Ship a time-series view, phase projection, signed coefficient table and parameter inspector. Analyze the deterministic independent drift at a verified positive interior equilibrium with its Jacobian. Use common random draws for one-at-a-time comparisons at the same timestep. Present sensitivity as changes in final simulated state. Single seeded trajectories and sweeps carry no field intervals.
4. Export parameter values, settings, seeds, solver version, generated time-series and sensitivity in JSON and CSV. Run numerical tests and repository-root desktop and mobile browser tests. Keep all original source material and research chapters intact.

## Evidence limits

Eqs. 9, 17 and 27 retain their documented inconsistencies. Missing calibration, raw observations, initial histories, original code and forecast training data prevent historical reproduction or field validation. The lab cannot reproduce Figs. 6–15. This implementation executes JavaScript only. The historical Python and MATLAB scripts remain evidence of separate examples, so no cross-language stochastic equivalence is claimed.

## Implementation and checks

- [Scenario manifest](../site/models/scenario-manifest.json) defines the scenario defaults, constant coefficients, dimensions, allowable controls and reasons for the illustrative choices. [Engine](../site/models/engine.mjs) derives effective coefficients from each submitted form. It uses a 32-bit linear congruential generator and Box–Muller normal draws with one increment per population per step in the noisy mode.
- Time-series and phase-space charts show a single path. The phase plot projects the first two states, so trajectories in the three-state system can cross in that projection. An open circle and filled square mark the initial and final samples.
- The independent drift uses `A x* = −r` to find an interior equilibrium. The implementation requires positive components strictly below the numerical cap and verifies the drift residual. At that point the Jacobian is `diag(x*) A`. The cubic Routh–Hurwitz test concerns the continuous deterministic drift. The tolerance is conservative near the classification boundary. Other boundary equilibria and global behavior are outside the calculation.
- The exploratory sweep varies one parameter at a time by ±10% and ±20% relative to its baseline. At zero, it uses 10% and 20% of the allowed range. Bounds clip the tested values and duplicate settings are removed. Runs use equal seeds and step counts when stochastic. The output is final synthetic state and safeguard counts. Sensitivity can change with the horizon, integration step, or selected path. It is not an uncertainty interval or a reconstruction of Fig. 15.
- JSON includes effective parameters, source page and citation role, solver version, units, seed, sample grid, states, sweep and diagnostics. CSV has one metadata record with an escaped JSON field, followed by trajectory and sensitivity records. Eq. 10 runs are deterministic and have a null seed.
- From the repository root, `node --test tests/site-smoke.test.mjs tests/ecology-engine.test.mjs` checks the prior prototype samples, seeded repeatability, deterministic equivalence and first step, time alignment, valid output bounds, validation, intervention switching, local equilibrium, sensitivity and exports. Timestep refinement is checked against a scalar analytical Eq. 10 solution and an independent RK4 benchmark for the three-population deterministic drift. These checks cover the specified examples and ranges, not a proof of stability or stochastic convergence for arbitrary models.
- With Playwright and Chromium available, run `node tests/ecology-browser.cjs docs/review`. Set `CHROME_BIN` to use an installed Chromium executable. The browser test uses a loopback server rooted at the repository. It checks keyboard execution, parameter changes, downloads, validation, source links and both layouts.
